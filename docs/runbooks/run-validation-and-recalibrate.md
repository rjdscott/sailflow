# Run validation and recalibrate

## When to use

Checking the physics model against the ORC Speed Guide polar, or updating a
free calibration parameter in `data/boats/j70.json`.

**Read this before running anything: on this branch (a55d993), there is no
physics model to validate yet.** `src/core/` has only `boat/validate.ts`
(schema/provenance checks on the boat JSON) and `types.ts`. Race and Dock
mode both run against `stubClient()` — fixed, hand-written plausible numbers
(`src/worker/client.ts`) — not a solver; `src/ui/dock/client.ts` even leaves
a `ponytail:` comment marking the exact line where a real
`SolverClient` swaps in. `make validate` / the `pnpm validate` script are an
explicit placeholder in `Makefile` ("Polar validation, local only
(placeholder for later)"), and `ASSUMPTIONS.md` still reads "None yet.
Populated by `calibration/fit.ts` in phase 02" because that file doesn't
exist here either. The polar-match harness described in
`docs/initial-prompt.md` (acceptance criterion 2, `validation/report.md`)
lands with the real solver, in a later phase than this branch — don't write
a `validation/report.md` runbook step that nothing produces.

## What you actually can run today

1. **Boat definition schema + provenance.** This is the real, working check
   in this branch — every numeric leaf in `data/boats/j70.json` has a
   provenance row naming a real source, and the file matches the
   `BoatDefinition` shape:

   ```bash
   pnpm exec vitest run src/core/boat/validate.test.ts
   ```

   Expected: all tests pass, including "accepts the committed J/70" and
   "every numeric leaf has a provenance row and every row names a known
   source".

2. **`data/boats/j70.json`'s `calibration` block is currently empty** (`{}`)
   — there is nothing to recalibrate yet. When free parameters do land, they
   belong there, and `ASSUMPTIONS.md`'s "Calibrated free parameters" table
   (generated by `node scripts/provenance.mjs`) is where the value and the
   fitting method get recorded — see `scripts/provenance.mjs`'s
   `assumptionsBody()`.

3. **Full doc/data gate**, which does run today and does check `data/`
   against `PROVENANCE.md`/`ASSUMPTIONS.md`:

   ```bash
   node scripts/provenance.mjs --check
   ```

## When the solver lands

Update this runbook in the same PR that adds `src/core/aero`, `src/core/hydro`,
`src/core/solve`, and the polar-match harness — at minimum: the exact command
that produces `validation/report.md`, the tolerance it's checked against and
why (`docs/initial-prompt.md`'s "Validation first" section requires a stated,
justified tolerance), and the recalibration workflow once `calibration/fit.ts`
exists. Don't guess those numbers into this file ahead of the code that
produces them.

## Failure modes

- **`pnpm validate` fails with "Missing script"**: there is no `validate`
  script in `package.json` yet, only the `Makefile` target that calls it —
  this is the placeholder described above, not a broken install.
- **Looking for `validation/report.md` and it doesn't exist**: correct,
  nothing generates it yet on this branch.
- **A newer commit than this branch already has a solver** (check
  `git log origin/main` — as of this writing `64495ce feat(core): calibrated
  J/70 VPP with hold-out validation, golden corpus and app integration` is
  ahead of this branch's `a55d993`): if you're working from a checkout that
  includes it, this runbook is stale for you — go read
  `src/core/aero`/`src/core/solve` and whatever validation script that PR
  added instead of trusting this file's "not implemented" framing.
