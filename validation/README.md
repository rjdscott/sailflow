# `validation/`

The harness that says whether the solver is any good. It only ever **reads**:
calibration is fitted in `calibration/` and frozen into `data/boats/j70.json`;
nothing here writes a knob (ADR 0007).

## Files

| File | What it is |
|------|------------|
| `compare.ts` | Shared plumbing: boat + polar loading, the ADR 0007 tolerances, the boat/calibration hashes, and `compareRow()` — one polar row replayed through the solver. |
| `invariants.test.ts` | The twelve solver invariants. Statements about signs, symmetry and monotonicity, never magnitudes, so they hold both before and after calibration. |
| `polar.test.ts` | The hold-out gate. Fails until calibration lands; that is correct. |
| `golden.test.ts` | Replays `golden/*.json` and asserts nothing moved. |
| `report.ts` | Writes `report.md`: polar comparison, gate verdict, model-vs-guide dock settings, honest weaknesses. |
| `golden/` | The golden corpus, generated by `pnpm golden` (owned by `calibration/`). |
| `report.md` | Generated. Not linted, not hand-edited. |

## Running

```bash
pnpm vitest run validation/invariants   # ~3 s
pnpm vitest run validation/polar        # ~1 s, the gate
pnpm vitest run validation/golden       # skips when the corpus is empty
pnpm vitest run validation              # all three
pnpm tsx validation/report.ts           # ~30 s, writes validation/report.md
pnpm validate                           # both of the above
```

## What the gate means

ADR 0007 splits calibration from validation; ADR 0012 sets the split by wind speed (fit all rows at TWS 6/10/12/16/20, hold out all rows at TWS 8/14). Hydro and rig/shape parameters are
fitted on **TWS 6, 10, 12, 16 and 20** VMG points. The gate is defined on what
the fit never saw:

- **Held-out TWS 8 and 14, VMG rows** (jib upwind, asymmetric downwind): boat
  speed within **3 %**, VMG angle within **2°**.
- **60°, 90° and 120° rows at every TWS**: boat speed within **5 %** (tier B).

A pass means the model generalises. A fit residual would mean only that the
optimiser worked. **Do not loosen a tolerance to make the gate green** —
changing one requires superseding ADR 0007.

Two conventions the ORC Speed Guide does not print, and which calibration must
share with the gate or the two disagree for no reason. Both are exported from
`compare.ts`:

```ts
POLAR_SEA_STATE = 1   // ripple; an ORC VPP polar always carries some wave drag
POLAR_CREW_KG         // boat.crew.maxKg — class-max crew, hiking hard
```

The polar prints fixed-angle rows for the **jib** table only (the asymmetric
table prints its VMG row alone), so the 60/90/120° rows are all jib rows and
are solved as such.

## Golden corpus format

`golden.test.ts` reads every `golden/*.json`. One file:

```json
{
  "boatHash": "3e0f6256",
  "calibHash": "319cc81d",
  "cases": [
    {
      "id": "upwind-10kt",
      "call": "trimmed",
      "controls": { "dock": { "upperTurns": 0, "lowerTurns": 0, "forestayMm": 0 }, "race": { "...": 0 } },
      "condition": { "twsKt": 10, "twaDeg": 42, "seaState": 1, "crewKg": 320, "sailset": "jib" },
      "result": { "...": "the SolveResult, JSON round-tripped" }
    },
    {
      "id": "vmg-up-12kt",
      "call": "optimal",
      "dock": { "upperTurns": 0, "lowerTurns": 0, "forestayMm": 0 },
      "opts": { "optimiseTwa": true },
      "condition": { "twsKt": 12, "twaDeg": 45, "seaState": 1, "crewKg": 320, "sailset": "jib" },
      "result": { "...": "the OptimalResult, JSON round-tripped" }
    }
  ]
}
```

- `boatHash` / `calibHash` come from `boatHash()` / `calibHash()` in
  `compare.ts`. Both are optional; when present and stale, the file is
  **skipped** with "run `pnpm golden`" rather than failed, because a
  deliberate recalibration should not look like a regression.
- Numbers must match within **1e-6 relative**; strings and booleans exactly.
- An empty `golden/` skips the whole suite.
